Class: ZCL_PO_CALCULATE

This global class encapsulates the business logic for calculating the total net price of a purchase order. It replaces the procedural function module zfm_iyh1hc2 with a modern, object-oriented, and S/4HANA-optimized implementation. The logic is contained within a single public static method.

CLASS zcl_po_calculate DEFINITION
  PUBLIC
  FINAL
  CREATE PUBLIC .

  PUBLIC SECTION.
    "! <p class="shorttext synchronized">Calculates capped total net price for a PO</p>
    "! @parameter iv_purchase_order | <p class="shorttext synchronized">Purchase Order Number</p>
    "! @parameter iv_po_document_type | <p class="shorttext synchronized">Purchase Order Document Type</p>
    "! @raising cx_sy_open_sql_db | <p class="shorttext synchronized">Database error</p>
    "! @returning rv_total_net_price | <p class="shorttext synchronized">Capped Total Net Price</p>
    CLASS-METHODS get_capped_total_net_price
      IMPORTING
        iv_purchase_order     TYPE ebeln
        iv_po_document_type   TYPE bstyp
      RETURNING
        VALUE(rv_total_net_price) TYPE bprei
      RAISING
        cx_sy_open_sql_db.

ENDCLASS.



CLASS zcl_po_calculate IMPLEMENTATION.

  METHOD get_capped_total_net_price.
    " Calculate total net price using an aggregate function for HANA optimization.
    SELECT SINGLE SUM( NetPriceAmount )
      FROM I_PurchaseOrderItem
     WHERE PurchaseOrder     = @iv_purchase_order
       AND PurchaseOrderType = @iv_po_document_type
      INTO @DATA(lv_total_net_price).

    " If the query fails, a CX_SY_OPEN_SQL_DB exception is raised and propagated.
    " If no items are found, SUM returns 0, correctly handling the business case.

    " Apply capping logic using the MIN intrinsic function for concise code.
    rv_total_net_price = min( val1 = lv_total_net_price, val2 = '10000' ).

  ENDMETHOD.

ENDCLASS.

Unit test: ZCL_PO_CALCULATE

This local test class provides unit tests for zcl_po_calculate. It uses the ABAP Test Double Framework to mock the CDS View I_PurchaseOrderItem, ensuring that the tests are isolated from the database and run predictably. The tests cover the main business scenarios: total price below the cap, total price above the cap, and no items found.

CLASS ltcl_test IMPLEMENTATION.

  METHOD setup.
    " Create a test double environment for the I_PurchaseOrderItem CDS view.
    go_cds_test_environment = cl_cds_test_environment=>create_for_multiple_cds(
      i_for_cds_views = VALUE #( ( 'I_PurchaseOrderItem' ) )

  ENDMETHOD.

  METHOD teardown.
    " Destroy the test double environment after tests are executed.
    go_cds_test_environment->destroy( ).
  ENDMETHOD.

  METHOD test_sum_below_cap.
    " Arrange: Create test data where the sum of net prices is below the 10000 cap.
    DATA(lt_po_items) = VALUE tt_po_items(
      ( PurchaseOrder = '4500000001' PurchaseOrderType = 'NB' NetPriceAmount = '4000.00' )
      ( PurchaseOrder = '4500000001' PurchaseOrderType = 'NB' NetPriceAmount = '3500.50' )
    ).
    go_cds_test_environment->insert_test_data( i_data = lt_po_items ).

    " Act: Call the method under test.
    DATA(lv_actual_price) = zcl_po_calculate=>get_capped_total_net_price(
      iv_purchase_order   = '4500000001'
      iv_po_document_type = 'NB'
    ).

    " Assert: Verify that the result is the correct sum.
    cl_abap_unit_assert=>assert_equals(
      exp = '7500.50'
      act = lv_actual_price
      msg = 'Failed: Sum should be below the cap.'
    ).
  ENDMETHOD.
